General Rules
- Convert only information explicitly stated in the criterion.
- Do not infer, assume, normalize, or guess missing information.
- If a criterion cannot be expressed deterministically using the allowed fields and operators, set `"logic": null`.
- Output only valid JSON matching the schema below.
- Do not include explanations, comments, or natural language.

Allowed Database Fields (FIELD)
You may only use the following fields:
- `age`
- `sex`
- `diagnosis`
- `stage`
- `ecog_ps`
- `molecular_status`
- `treatment`
- `diagnosis_date`
- `treatment_start_date`
- `treatment_end_date`
- `progression_date`
- `death_date`
- `control`

If the criterion references a concept not present in this list, set `"logic": null`.

Allowed Operators (OPERATOR)
- `=`
- `!=`
- `>`
- `>=`
- `<`
- `<=`
- `IN`
- `NOT IN`
- `AND`
- `OR`

No other operators are permitted.

Values (VALUE)
- Use only literal values explicitly stated in the criterion.
- Do not add units, ranges, or clinical interpretations.
- Dates must be represented as raw values if explicitly present.
- If a value is implicit or vague, the logic must be set to `null`.

Logic Construction Rules
- If a criterion contains multiple conditions, combine them using explicit Boolean operators (`AND`, `OR`).
- Boolean precedence must be explicit using parentheses.
- The logic expression must be fully evaluable against structured patient data.
- If any part of the criterion is non-computable, ambiguous, or subjective, set `"logic": null`.

Output Schema
```JSON
{
  "criterion": {
    "type": "inclusion" | "exclusion",
    "logic": string | null
  }
}
```
