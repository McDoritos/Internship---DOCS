General Rules
- Convert only information explicitly stated in each criterion.
- Do not infer, assume, normalize, or guess missing information.
- Always produce a structured `"logic"` object for every criterion.
- Never return `"logic": null`.
- If a criterion cannot be fully expressed using the allowed fields and operators, create the best possible partial or fallback structured representation while preserving the original meaning as faithfully as possible.
- Output only valid JSON matching the schema below.
- Do not include explanations, comments, or natural language outside the JSON structure.

Allowed Database Fields (FIELD)
You should prioritize using the following fields whenever possible:
- `age`
- `sex`
- `diagnosis`
- `stage`
- `ecog_ps`
- `molecular_status`
- `diagnosis_date`
- `treatment`
- `treatment_name`
- `treatment_start_date`
- `treatment_end_date`
- `progression_date`
- `death_date`
- `control`

If a criterion references a concept not present in this list:
- Do not discard it.
- Do not return null.
- Represent it using a fallback structured object while preserving the original text.

Allowed Operators (OPERATOR)
Use these operators whenever the criterion can be mapped to the schema:
- `=`
- `!=`
- `>`
- `>=`
- `<`
- `<=`
- `IN`
- `NOT IN`
- `AND`
- `OR`

If a criterion cannot be represented using these operators alone, preserve it using a fallback structured representation instead of null.

Values (VALUE)
- Use only literal values explicitly stated in the criterion.
- Do not add units, ranges, or clinical interpretations unless explicitly present.
- Dates must be represented as raw values if explicitly present.
- If a value is vague or not computable, preserve the criterion using a fallback structured object rather than null.

Logic Construction Rules
- If a criterion contains multiple conditions, combine them using explicit Boolean operators (`AND`, `OR`) whenever possible.
- Boolean precedence must be explicit through nested structure.
- If only part of the criterion is computable, represent the computable part and preserve the remaining part in fallback structured form.
- If the criterion is entirely outside the schema, preserve it in fallback structured form.
- Never omit a criterion.
- Never return `"logic": null`.

Fallback Representation Rules
When a criterion cannot be fully mapped to the allowed schema, use one of the following fallback structures:

For partially or fully unmapped criteria:
```json
{
  "unmapped": true,
  "source_text": "original criterion text"
}
```

For mixed computable + non-computable criteria:
```json
{
  "operator": "AND" | "OR",
  "conditions": [
    { computable structured condition },
    {
      "unmapped": true,
      "source_text": "unmapped part of the criterion"
    }
  ]
}
```

```json
{
  "inclusion_criteria": [
    {
      "id": integer,
      "text": string,
      "logic": object
    }
  ],
  "exclusion_criteria": [
    {
      "id": integer,
      "text": string,
      "logic": object
    }
  ]
}
```
